# v17 / v17.1 隔离测试网验收手册与证据清单

适用范围：`release/a9-rc1` 现役 `v17/` 四合约、Worker、独立发币程序、Bot 与小程序。初始审查基线为 `500b154`；每次执行必须记录新的完整提交哈希和产物 SHA-256，不能沿用旧版本通过结论。

**这是执行与取证规范，不是“测试网已全部通过”的声明。** 本次文档更新未部署候选环境、未配置密钥、未签名、未广播、未迁移远程数据库，也未打开生产总闸。

## 1. 四种证据不能互相替代

| 证据层 | 能证明什么 | 不能替代什么 |
| --- | --- | --- |
| Node / Python / Miniflare 本地测试 | 代码规则、数据库并发、故障与幂等断言 | 公网RPC、真实钱包签名与到账、远程D1、Telegram真机 |
| 浏览器 Demo / HTTP 夹具 | 路由、视觉、缺值、错误恢复、模式隔离 | 真实Telegram身份、ton_proof、链上收付款 |
| Acton 本地 TVM | 合约执行、时钟边界、资金守恒、正式和缩短参数 | 测试网实际交易、外部服务联调 |
| 隔离 Testnet 闭环与真机 | 同一候选版本真实签名、到账、账本和恢复 | 主网钱包、主网部署授权、生产可用性 |

状态统一为 `通过 / 失败 / 待执行 / 受阻 / 不适用（原因）`。没有所需证据的项保持待验。模拟哈希、Mock钱包、Testnet交易均不得标为主网实测。

## 2. 环境隔离与准入门禁

1. 记录候选HEAD、四份v17产物指纹、Worker/前端/Acton版本。禁止修改锁定合约或产物以使测试通过；重编译和测试若需写产物，使用隔离临时副本并比对指纹。
2. 使用独立Testnet合约、钱包、两个独立热钱包、D1、Bot、域名与签名进程。主网 7 个角色对应的 6 个独立 W5 地址（当前锁定包 `keeper` 与 `roundOpener` 合用同一地址，合设仍需业主书面确认，不自行更换地址或生成新主网钱包）及生产 `a9mini-v15-prod` 不得作为测试对象。
3. `worker/wrangler.toml` 的 `env.candidate` 是配置骨架，数据库ID占位、域名和四个地址仍为空时不能声称就绪。`env.testnet` 中的既有地址也须核实代码哈希和参数，不能只凭地址存在认定是本轮v17产物。
4. 凭据由业主在目标机器安全配置；只记录键名、用途、来源位置与可用性，禁止记录值。旧BAM只读，不改写、不把凭据迁入项目。RPC Key必须实际通过对应网络，非空不代表有效。
5. W5版本、workchain、网络global ID、walletId/subwallet参数与公开派生地址须精确核对。CLI帮助支持 `v5r1` 不等于正式W5地址已匹配；模型生成的V4R2不替代业主正式W5。
6. 候选前端和API均为 `testnet`，钱包链标识 `-3`；主网为 `-239`，混用立即停止。
7. **生产四道闸始终保持关闭**：前端 `liveFundsEnabled=false`，生产 `A9_PRESALE_OPEN=0`、`A9_CHEST_OPEN_ENABLED=0`、`A9_BROADCAST_ENABLED=0`。候选写操作仅在明确批准的隔离环境开放，URL不得开闸，不能修改生产配置方便测试。
8. 候选部署、测试网广播、远程候选迁移、测试Bot Webhook、密钥导入与签名环境配置须核对具体目标及授权。只读审查阶段不执行。远程迁移前确认库ID、备份及全部迁移文件；本手册不构成生产写操作授权。

## 3. 参数档与时间证明边界

单源为 `ops/scripts/lib/v15-core.mjs` 的 `PROFILES`，实际部署值须用getter核验。

| 项目 | testnet正式时长档 | testnet-fast缩短档 |
| --- | ---: | ---: |
| 锁仓期 | 86,400s | 120s |
| 头矿窗口 | 21,600s | 30s |
| 冲价期 | 43,200s | 60s |
| 时段数/最少达标数 | 12/8 | 12/8 |
| 每个等长时段 | 3,600s | 5s |
| 超时中止等待参数 | 604,800s | 120s |
| 奖金解锁时长 | 1,209,600s | 600s |

两档均为Testnet，最低锁仓100 A9，奖金5×封顶。缩短档禁止用于主网。

- 缩短档600秒解锁仅证明缩短参数全流程，不得写成“真实等待14天已验收”。正式14天比例、参数和边界由正式参数本地时钟测试及getter证明；真实日历观察另列长跑记录。
- AbortRound的准确边界是 **now >= stakeCloseAt + observationSeconds + abortTimeoutSeconds**，不是简单从开轮起等7天。记录三个输入以及边界前后秒数。
- 缩短档每段5秒，不得标成真实1H TWAP。正式12根1H采集、时间对齐、缺段/重复/陈旧价格另测，手工达标数不替代行情采集证据。

```bash
(cd v16 && shasum -a 256 -c ci/artifacts.sha256)
```

额外执行当前支持的数据库并发和合约专用套件，记录完整命令、运行时、通过数、跳过数与原因。未运行的Miniflare/合约套件不能计入通过；Node顶层子测试数与文件内自行报告的断言数分开记录。

下列已有CLI命令仅在目标Testnet变量已安全配置并核对后执行，不会要求广播：

```bash
node ops/scripts/deploy-v15.mjs --protocol v17 --profile testnet-fast --strict --dry-run
node ops/scripts/round-ops.mjs --protocol v17 --profile testnet-fast --action open-round --round 1 --twap 0 --target 232000 --strict --dry-run
node ops/scripts/round-ops.mjs --protocol v17 --profile testnet-fast --action settle-round --round 1 --qualified 8 --candle-hash 0x1234 --strict --dry-run
node ops/scripts/round-ops.mjs --protocol v17 --profile testnet-fast --action abort-round --strict --dry-run
```

- 开轮示例只适用于链上下一轮确为1、初始基价116000 USD_E8的隔离实例。后续轮的轮号、走廊和时间须重新核对。
- 结算示例的8与0x1234是测试控制向量，不是采集证据。行情验证使用已有 `--candles-file <JSON> --target <USD_E8> --stake-close-at <UNIX_SEC>` 并保存完整输入；主网禁止手工达标数旁路。
- `round-ops.mjs`兼容调用名为 `round_ops_v16.tolk` 的脚本；`--protocol v17`使它从v17项目加载现役类型，兼容文件名不等于使用v16产物。
- 不添加尚未实现的CLI参数；若预检修复新增选项，按实际代码同步本节后再执行。
- RPC、完整派生地址、部署包和签名来源未核实时，退出码0不构成通过；已知假绿修复前保持阻断。
- 真正测试网交易由明确授权的测试客户端或钱包逐笔执行并留证；本手册不提供一键开生产闸命令。

## 9. 收口与主网边界

测试网收口需当前全栈与专用套件通过，C/W/U矩阵完成或有明确批准的例外，真实交易/D1/余额/预算无差额，故障恢复可复现，修复后的相关场景复测且独立验收。不能删除失败测试、改低预期或省略链上证据来收口。

随后另行核验主网钱包来源、Mainnet Key、锁定部署包/角色/产物、Gas储备、生产D1与配置、签名来源和真机入口。**测试网全绿不等于主网部署授权。** 主网部署、铸币弃权、注资、生产迁移、Secrets写入、Bot切换及资金放量仍需各波次单独书面授权。

## 附录：部署预检新增签名来源检查

`deploy-v15.mjs` 当前会实际验证RPC主网/测试网零状态指纹与元数据。`--skip-metadata-probe`不再允许绕过检查。主网还会校验锁定部署包文件指纹、StateInit地址/代码、关键参数和全部角色签名来源。

- 本地自动签名：默认 `--deployment-mode local`。主网必须额外提供 `--signer-manifest <本机公开描述JSON路径>`；描述不含助记词/私钥。
- 外部钱包部署：`--deployment-mode external --signer-manifest <本机公开描述JSON路径> --dry-run`。外部部署通过只会给出 `readyForExternalDeployment:true`，不会给出 `readyForExecute:true`；CLI不能用此模式广播，实际部署仍须独立授权并使用控制台。
- 主网描述格式：`{"network":"mainnet","roles":{...}}`，roles必须包含deployer、treasury、keeper、roundOpener、teamWallet、presaleHotWallet、promoHotWallet。
- 本地角色：`{"mode":"local","address":"完整公开地址","walletName":"Acton钱包名"}`。预检通过只读 `inspect_signers.tolk` 解析本机实际地址，不能只声明一个地址。
- 外部角色：`{"mode":"tonconnect|hardware|multisig","address":"完整公开地址","source":"设备或保管来源说明，不含秘密","version":"v5r1","stateInit":"公开StateInit BOC"}`。StateInit必须精确对应地址。硬件/手机签名能力仍需后续本人连接验收；公开描述不证明设备在线或已获交易授权。
- 任一必需检查失败时打印 `readyForExecute:false` 并返回非0。`readyForPayouts`仅表明来源可解析且当前两热钱包采用本地模式，不代替余额、库存、daemon故障恢复和真实到账验收。

追加本地回归命令：

```bash
node --test ops/scripts/deploy-readiness.test.mjs ops/scripts/deploy-console.test.mjs worker/tests/payout-verification-fail-closed.test.mjs
```

### 主网奖励结算暂时封锁

在链上终局、实际通关奖金、真实参与者与随机种子证据核验服务完成并独立验收前，主网 `POST /api/admin/v17/stake-referral/settle` 与 `POST /api/admin/v17/airdrop/draw` 即使管理员认证成功也返回 `503 V17_CHAIN_SETTLEMENT_UNAVAILABLE`，不入账。不存在配置开关绕过该保护。测试网可验证现有引擎，但不得据此宣布波次3就绪；解除代码级封锁属于后续独立验收变更。
