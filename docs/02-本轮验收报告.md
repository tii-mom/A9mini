## 3. 语法与接口

- 19 个 JS 模块全部通过 `node --check`（复制为 `.mjs` 解析）。
- BAM demo API 实测返回：`/api/health` 200；`/api/config`、`/api/rounds`、`/api/rounds/:id`、`/api/rounds/:id/candles`、`/api/stats`、`/api/reward-ledger` 均为 `{ok:true,data,ts}` 信封。
- 焦点轮选择按 BAM `focusRound` 口径：进行中最高轮 → 最近已开启轮 → 第一轮。本轮演练读到 R4 `STAKING_OPEN`，`secondsRemaining` 来自服务端。
- 演示数据从 BAM 真实接口样本构造（R3 观察期：12 段已收盘 / 8 段达标 / 第 13 段进行中），页面明确标识为「演示模式」。

## 4. 视口与视觉检查

- 390×844 与 360×780 均实测；无横向溢出，长金额（700,000,000 A9）不换行截断。
- 固定底栏位于 `env(safe-area-inset-bottom)`；`.app-main` 底部留白 110px。实测底栏只覆盖滚动中的雷达下半部分，**不遮挡主操作按钮**。
- 观察页卡片：倒计时、8/16 已达标、还差 8 个达标时段同屏；奖励区明确「估算 / 不构成承诺 / 结算后以实际结果为准」。
- 雷达：已确认（实心）、进行中（`13*`，动画）、未开盘（暗色）三态可辨。
- 「我的」：可领取 0 A9（真实零值）→ 参与中 → 待解锁 → 凭证/海报/设置顺序正确；真实模式未连接时显示「金额不可读取」而不是假余额。

## 6. 失败与差异说明

- 自动化首轮 15/19：4 项失败来自验收脚本 URL 拼接错误（`?mode=live/#/...` 把斜杠写进 query），修正脚本后 19/19；**不是产品缺陷**。
- 另 1 项真实缺陷：「真实模式阶段胶囊仍可点击」，已改为静态标签后通过。
- 各页有 1 条浏览器 console 错误 `ERR_CONNECTION_CLOSED`，来自离线环境加载 `unpkg` TON Connect / Telegram SDK / Google Fonts CDN；页面 JS 无异常，只读功能不受影响。真机联网环境需复测。
- BAM 在本轮期间出现新的未提交改动：`web/src/features/miniapp/estimate.ts`、`worker/src/me-position.ts`，以及更早的 `candidate-contracts/v14/`、`docs/82_V14_PROTOCOL_SPEC.md`。这些属于另一窗口在途工作，**本轮未读取内容、未修改、未基于其迁移**。
