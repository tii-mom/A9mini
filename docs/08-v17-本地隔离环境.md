# v17 独立测试环境：本地准备与公网交接

当前已准备的是**本地隔离候选环境**，不是已经部署的公网测试网，也没有进行链上交易。

## 已运行的本地组件

- 前端入口：`http://127.0.0.1:8097/?mode=live#/challenge`。
- 准备状态：`http://127.0.0.1:8097/__candidate/status`。
- 同一入口代理现役 `worker/src/cf-worker.mjs`，使用真实本地 workerd/D1。
- 数据仅保存到 `~/.local/share/a9-v17-candidate/d1`，与生产 D1、现有预览及项目文件分开。
- 按文件指纹在本地顺序应用 `0001..0015`；重启不重复应用，历史迁移指纹发生变化则拒绝启动。
- 前端强制 `live + lockMode + testnet`，资金总闸关闭。服务仅监听127.0.0.1；写请求全部返回403。
- Worker对外网络连接禁止，没有加载Bot Token、RPC Key、管理员密钥、助记词或签名器。
- 尚未配置合约与热钱包时，`/api/config`、`/api/health` 返回 `503 CANDIDATE_CONFIG_INCOMPLETE`，这是预期保护，不得注入演示金额来消除错误。
- 静态资源缺失返回404，禁止把HTML首页当JavaScript文件返回。
- D1不授权 `PRAGMA integrity_check`，故只验证迁移记录与数据库可读性；状态明确标注该完整性命令未运行，不能称为通过。

## 启动与检查

在项目根目录执行：

```bash
node ops/scripts/local-v17-candidate.mjs --smoke
node ops/scripts/local-v17-candidate.mjs
```

首条命令检查后退出；第二条持续运行，Ctrl+C停止。可用 `--port 8097` 显式指定独立端口。不提供remote/execute模式。

需要Node、esbuild、Miniflare。优先使用本机已安装的稳定版本或npm缓存；不自动下载、不创建项目node_modules、不改锁文件。若需显式指定已有模块，可设置 `ESBUILD_MODULE` / `MINIFLARE_MODULE` 为已有本地模块入口。新版本兼容性必须先通过测试，不能直接套用不兼容运行时。

回归：

```bash
node --test ops/scripts/local-v17-candidate.test.mjs
```

测试使用临时独立目录，检查15份迁移、持久化重启、地址/模式隔离、资金入口关闭、真实JS资源与404，不联系公网也不发送交易。
